# 02 首次部署与能力验收

[返回入口](../README.md)

## 前置条件

确认管理入口可保存状态或有获准的私有状态存放处；至少一个执行端可访问所需文件；用户明确允许使用相应工具和目标对话。无须先购买复杂团队框架。具体软件安装与账号配置采用当前产品官方文档，本仓库不提供固定命令或假定版本。

## 建立私有登记

复制[环境登记模板](../templates/environment-register.md)到不公开的位置填写。记录设备角色、稳定标识、目标对话类型、确认日期、允许的发送路径、回执读取方式及断线行为。真实标识不进入公共 Git 仓库。

不要仅记录昵称。对于相似名称，应把设备和目标对话作为一对核实；同一个用户名不能证明同一台电脑。

## 分层验收

| 层级 | 操作 | 通过证据 | 失败含义 |
|---|---|---|---|
| 连接 | 使用受支持的设备列表/连接接口 | 目标设备及当前连接状态匹配 | 暂不可访问，不代表文件损坏 |
| 发现 | 查看当前上下文可用工具 | 所需工具列出 | 缺工具不等于插件未安装 |
| 调用 | 做一次无害读取 | 正确目标的真实响应 | 需要区分注册、启动、权限和运行错误 |
| 投递 | 用户授权后发送无业务作用的测试 | 工具确认及目标端收到 | 不能仅凭管理端成功状态断言送达 |
| 回执 | 读取目标回复 | 唯一测试标识匹配 | 无回执不自动等于未送达 |
| 恢复 | 经授权重连或正常重启后复测 | 同一路径仍能成功 | 一次成功不足以声明持久修复 |

先达到当前任务需要的层级，不为简单只读任务强制做消息投递测试。测试本身会改变目标对话时，应具有用户授权。未经允许不使用界面自动化代替接口。

## 能力登记方式

记录“可用、不可用、未验证、暂时失败”及最近检查时间，不只填一个笼统的支持/不支持。已验证结果必须关联当时的设备、任务类型、工具和会话上下文。

## 启动一个真实任务前

用[任务单](../templates/task-brief.md)确认结果与验收条件，检查当前运行环境、工作副本和用户数据基线。没有确认身份和目录之前不写入。接口缺失时先确定备用方式及授权，不悄悄新建另一种对话。
