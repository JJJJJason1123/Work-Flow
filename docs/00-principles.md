# 00 原则与边界

[返回入口](../README.md)

## 目标

降低用户协调负担，让任务在授权范围内持续推进，并使每个完成声明有证据。效率不是单纯增加并行 Agent，而是减少错误路由、重复执行、无效验证和反复澄清。

## 固定原则与可调整策略

| 固定原则 | 可按任务调整的策略 |
|---|---|
| 不捏造事实、状态和完成证据 | 计划粒度与说明长度 |
| 不越过用户明确约束或平台权限 | 模型与推理强度（用户指定时不得擅改） |
| 不确定送达先核对，避免重复动作 | 采用直接接口、获准中转或人工转交 |
| 保护用户数据与成果 | 是否需要独立审查、检查覆盖深度 |
| 用户最新有效方向需要传达与落实 | 独立研究能否并行 |
| 错误及时说明、能修的主动修 | 状态更新频率与汇报格式 |

## 术语

- **管理入口**：用户交付目标并接收结果的主对话或系统。
- **管理者**：维护范围、队列、路由、状态和交付的角色。
- **执行者**：完成具体工作项的角色；不是所有执行者都需要独立模型或进程。
- **中转**：在管理入口与目标执行对话之间传递已授权指令的路径；不是业务决策者。
- **原生本地对话**：由本地客户端管理的特定类型对话，须通过实际元数据或产品机制确认。
- **本机执行的托管任务**：管理和会话可能由服务端维护，而命令在已连接电脑执行；不自动等同原生本地对话。
- **云任务**：工作在云环境中执行。是否能访问本地资料另行确认。
- **能力**：当前执行上下文实际可调用且经必要验证的工具，而不是仅显示为已安装的插件。
- **回执**：目标端确认已收到指定请求的证据，不等于工作已完成。

## 边界

这套流程描述管理方法，不保证平台具备任意对话直发、持久执行、工具重载、全机活动任务枚举或自动完成通知。没有能力时，应明确受阻的是哪一步，提供获准的替代方式；不得把计划写成既成事实。

文档中的建议不是对专业判断、法律责任或用户审批的替代。最终专业签署与高风险决定保留在人类和合规流程中。

## 处理不确定性

使用三个层次：已证实事实、待验证假设、尚未知信息。事实应有来源和时间；假设应有可区分的实验；未知信息应说明它阻碍哪一步。不把一次成功推广为长期可靠，也不把一次失败推广为永远不支持。
